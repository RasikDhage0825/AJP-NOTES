CHAPTER 1

Introduction to Spring Framework and its Architecture

Point 1.1

What is Spring Framework?

📖 DEFINITION

Spring is a lightweight, open-source Java framework used to build enterprise-level applications easily. It handles the "plumbing" work of an application — like creating objects and connecting them — so the developer can focus only on writing business logic.

Point 1.2

Why do we need Spring?

Before Spring, Java EE (J2EE) applications required a lot of boilerplate code (repetitive setup code) and tightly-coupled classes, which made testing and maintenance hard. Spring solves this by providing:

  • ✔
    Loose coupling between classes using Dependency Injection.
  • ✔
    Ready-made modules for database access, transactions, web MVC, security, etc.
  • ✔
    POJO-based development — you can build enterprise applications using simple Plain Old Java Objects instead of heavy, complex classes.
  • ✔
    Integration support with other frameworks like Hibernate, Struts, JSF, etc.
Point 1.3

Features of Spring Framework

Feature Meaning in Simple Words
Lightweight Minimal overhead; uses POJOs instead of heavy EJB-style objects.
IoC (Inversion of Control) Spring creates and manages objects for you instead of you creating them with new.
Aspect-Oriented Programming (AOP) Common tasks like logging or security can be added separately without touching business code.
MVC Framework Built-in support to build web applications using Model-View-Controller pattern.
Transaction Management Simplifies handling database transactions (commit/rollback).
Integration Friendly Works smoothly with JDBC, Hibernate, JPA, JMS and other technologies.
Point 1.4

Spring Framework Architecture (Modules)

Spring is not a single big library — it is divided into many small modules grouped into layers. A developer can pick only the modules needed for the project.

BLOCK DIAGRAM — SPRING FRAMEWORK LAYERED ARCHITECTURE

Layered stack representation (Core Container forms the base):

Test Module (JUnit / TestNG Integration)
↓
Spring MVC / Web Module (Web, Servlet, WebSocket, Portlet)
↓
AOP & Instrumentation (Aspects, AOP, Instrumentation)
↓
Data Access / Integration Layer (JDBC, ORM, OXM, JMS, Transactions)
↓
Core Container (Foundation Layer) (Core, Beans, Context, SpEL)
The Core Container is the foundation — it manages beans and dependencies. Every other module is built on top of it.

Core Container — the heart of Spring

  • •
    Core & Beans: Provides the fundamental IoC and Dependency Injection features.
  • •
    Context: Adds enterprise-level services on top of the Core module (like ApplicationContext).
  • •
    SpEL (Spring Expression Language): Allows querying and manipulating objects at runtime using expressions like #{}.
💡 KEY POINT TO REMEMBER

Everything in Spring revolves around the Core Container. It is responsible for creating objects (called Beans) and injecting their dependencies — this is the base on which MVC, AOP, and Data Access modules work.

🎓 EXAM TIP

If asked to "draw Spring architecture," always draw it as layers with the Core Container at the bottom, since every other module depends on it.

CHAPTER 2

Dependency Injection (DI) and Inversion of Control (IoC)

Point 2.1

What is Inversion of Control (IoC)?

📖 DEFINITION

Inversion of Control is a design principle in which the control of creating and managing objects is transferred from the programmer to a container/framework (in our case, the Spring Container). Since the controlling of Java objects and their life cycle is no longer done by the developer, it is called "Inversion" of Control.

❌ In Traditional Programming
Engine engine = new Engine();

The class itself creates its dependency using new. Result: tightly coupled code.

✔ With IoC (Spring)
Spring Container injects Engine

The Spring Container creates the Engine object and gives (injects) it to the class that needs it.

Main responsibilities of the Spring IoC container: creating objects, managing them, wiring dependencies together, and making the application easily configurable.

Point 2.2

What is Dependency Injection (DI)?

📖 DEFINITION

Dependency Injection is the actual technique used to implement IoC. It means supplying (injecting) the required objects (dependencies) of a class from outside, instead of the class creating them itself.

Point 2.3

Block Diagram — Without DI vs With DI

BLOCK DIAGRAM — WITHOUT DI VS WITH DI
WITHOUT DI (Tight Coupling)
Car class
↓ creates using "new"
Engine object
VS
WITH DI (Loose Coupling)
Spring Container
↓ injects Engine into Car
Car class ← receives Engine
In DI, the Car class does not create the Engine — the Container hands it over, so Car and Engine remain loosely coupled.
Point 2.4

Types of Dependency Injection

Type How it works When to use
1. Constructor Injection Spring passes the dependency through the class constructor when the object is created. Best for mandatory / required dependencies.
2. Setter Injection Spring calls the setter method of the class to supply the dependency after the object is created. Best for optional dependencies, or ones that may change after the object is built.
Point 2.5

Autowiring — A Spring Feature

⚙ AUTOWIRING — A SPRING FEATURE

Autowiring is not counted as a separate "type" of DI in exam answers. It is a Spring feature that automatically performs Constructor or Setter Injection for you, by matching dependencies by type or name, so you don't have to wire every bean manually in XML.

Point 2.6

Code Programs: Setter & Constructor Injection

▶ Example: Setter Injection

Java Engine.java & Car.java 
public class Engine {
    public void start() {
        System.out.println("Engine started...");
    }
}

public class Car {
    private Engine engine;

    // Setter method used by Spring to inject dependency
    public void setEngine(Engine engine) {
        this.engine = engine;
    }

    public void drive() {
        engine.start();
        System.out.println("Car is running");
    }
}
XML applicationContext.xml (Setter Injection Configuration) 
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
       http://www.springframework.org/schema/beans/spring-beans.xsd">

    <bean id="engine" class="Engine"/>

    <bean id="car" class="Car">
        <property name="engine" ref="engine"/>
    </bean>

</beans>

▶ Example: Constructor Injection

Java Car.java (Constructor Injection) 
public class Car {
    private final Engine engine;

    // Constructor used by Spring to inject dependency
    public Car(Engine engine) {
        this.engine = engine;
    }

    public void drive() {
        engine.start();
        System.out.println("Car is running");
    }
}
XML applicationContext.xml (Constructor Injection Configuration) 
<bean id="engine" class="Engine"/>

<bean id="car" class="Car">
    <constructor-arg ref="engine"/>
</bean>
Java Main.java (Testing the Application) 
import org.springframework.context.ApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class Main {
    public static void main(String[] args) {
        ApplicationContext context =
            new ClassPathXmlApplicationContext("applicationContext.xml");

        Car car = (Car) context.getBean("car");
        car.drive();
    }
}

/* OUTPUT:
Engine started...
Car is running
*/
💡 KEY POINT TO REMEMBER

IoC is a design principle, while Dependency Injection (DI) is a technique used to implement IoC. Whenever the Spring Container supplies a dependency to a class, that is DI in action, and DI is simply how Spring applies the broader IoC principle in practice.

CHAPTER 3

Spring Container and Bean Life Cycle

Point 3.1

What is the Spring Container?

📖 DEFINITION

The Spring Container is the core part of the framework responsible for creating objects (beans), configuring them, wiring their dependencies together, and managing their complete life cycle from creation to destruction. It reads the required configuration information from an XML file, Java annotations, or Java-based configuration classes.

Bean Definition: Any object which is created, configured, and managed by the Spring Container is called a Bean.

Point 3.2

Types of Spring Container

Container Description
BeanFactory The most basic container. Provides basic DI support. Loads beans lazily (only when requested).
ApplicationContext An advanced container built on top of BeanFactory. Supports AOP, event propagation, internationalization, and loads beans eagerly (at startup). This is the most commonly used container in real projects.

CHAPTER 4

XML-Based and Annotation-Based Configuration

Point 4.1

XML-Based Configuration

📖 DEFINITION

In this approach, beans and their dependencies are declared inside an XML file (like applicationContext.xml). The Spring Container reads this file to know which objects to create and how to wire them.

XML Example: student-context.xml 
<beans xmlns="http://www.springframework.org/schema/beans" ...>
    <bean id="student" class="Student">
        <property name="name" value="Rahul"/>
        <property name="age" value="21"/>
    </bean>
</beans>
Java Student.java 
public class Student {
    private String name;
    private int age;

    public void setName(String name) { this.name = name; }
    public void setAge(int age) { this.age = age; }

    public void display() {
        System.out.println("Name: " + name + ", Age: " + age);
    }
}
Point 4.2

Annotation-Based Configuration

📖 DEFINITION

Instead of writing XML, dependencies are configured directly in the Java class using special annotations. Spring scans the classes (Component Scanning) and automatically creates and wires the beans.

Annotation Purpose
@Component Marks a class as a generic Spring-managed bean.
@Autowired Tells Spring to automatically inject the required dependency.
@Configuration Marks a class as a source of bean definitions (replaces XML file).
@Bean Used inside a @Configuration class to manually declare a bean.
@ComponentScan Tells Spring which package to scan for annotated classes.
Point 4.3

Annotation Code Implementation

Java Engine.java & Car.java (Annotation Based) 
import org.springframework.stereotype.Component;

@Component
public class Engine {
    public void start() {
        System.out.println("Engine started using annotation config");
    }
}

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

@Component
public class Car {
    @Autowired
    private Engine engine;

    public void drive() {
        engine.start();
        System.out.println("Car is running (Annotation Config)");
    }
}
Java AppConfig.java (replaces XML file) 
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;

@Configuration
@ComponentScan(basePackages = "com.example")
public class AppConfig {
}
Java Main.java 
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class Main {
    public static void main(String[] args) {
        AnnotationConfigApplicationContext context =
            new AnnotationConfigApplicationContext(AppConfig.class);

        Car car = context.getBean(Car.class);
        car.drive();
    }
}
Point 4.4

XML vs Annotation — Quick Comparison

Basis XML Configuration Annotation Configuration
Location of config Separate XML file Inside the Java class itself
Readability Configuration and code are separated, can get long Compact, config sits close to code
Flexibility Can change beans without recompiling code Requires recompilation to change
Best suited for Large legacy projects, external library beans Modern applications, faster development
CHAPTER 5

Spring MVC Architecture and DispatcherServlet

Point 5.1

What is Spring MVC?

📖 DEFINITION

Spring MVC is a module of Spring used to build web applications following the Model-View-Controller design pattern, which separates an application into three parts: Model (data), View (UI), and Controller (request-handling logic).

Component Role
Model Holds application data (usually POJOs / data from database).
View Displays data to the user (JSP, Thymeleaf, HTML page).
Controller Handles client requests, processes them, and returns the appropriate response/view.
Point 5.2

DispatcherServlet — The Front Controller

📖 DEFINITION

DispatcherServlet is the heart of Spring MVC. It acts as the Front Controller — every single HTTP request first arrives here, and it decides which controller should handle it, then sends the final response back to the browser.

💡 KEY POINT TO REMEMBER

DispatcherServlet follows the Front Controller design pattern — a single entry point for all requests, which then routes them appropriately. This centralises request handling and makes the application easier to manage.

Point 5.3

Spring MVC Request Flow (Interactive 8 Steps)

Interactive Request Flow Simulator:
Step 1 of 8 Active
BLOCK DIAGRAM — SPRING MVC REQUEST FLOW
1
Client / Browser sends HTTP Request User clicks a link or submits a form
↓
2
DispatcherServlet (Front Controller) Receives the request first; acts as central coordinator
↓
3
Handler Mapping (finds correct Controller) Checks which Controller method matches the requested URL
↓
4
Controller (executes business logic) Executes logic (e.g. database fetch) & returns Model + View name
↓
5
Model + View Name returned to DispatcherServlet Controller hands result back to DispatcherServlet
↓
6
View Resolver (locates actual JSP/HTML page) Converts logical view name (e.g. "home") to file path (/WEB-INF/views/home.jsp)
↓
7
View (JSP) renders data View is populated with Model data
↓
8
HTTP Response sent back to Client DispatcherServlet sends the final HTML response back to browser

Step-by-Step Explanation (Simple Words)

  1. The user clicks a link / submits a form → a request goes to the server.
  2. DispatcherServlet receives the request first — it does not process business logic itself, it just delegates.
  3. The Handler Mapping checks which Controller method matches the requested URL.
  4. The matched Controller executes the logic (e.g., fetching data from a database) and returns a Model (data) and a View name.
  5. The View Resolver converts the logical view name (e.g., "home") into the actual file path (e.g., /WEB-INF/views/home.jsp).
  6. The View is rendered with the Model data and sent back to DispatcherServlet.
  7. DispatcherServlet sends the final HTML response back to the browser.
Point 5.4

Example: Simple Spring MVC Controller

Java HomeController.java 
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HomeController {

    @GetMapping("/welcome")
    public String showWelcomePage(Model model) {
        model.addAttribute("message", "Welcome to Spring MVC!");
        return "welcome"; // logical view name -> welcome.jsp
    }
}

    </servlet-class>
</servlet>

    <servlet-name>dispatcher</servlet-name>
    <url-pattern>/</url-pattern>
</servlet-mapping>
JSP welcome.jsp (View) 
<html>
<body>
    <h2>${message}</h2>
</body>
</html>

Database Connectivity — Spring JDBC & Spring + Hibernate

Point 6.1

Why Spring JDBC?

📖 DEFINITION

Spring JDBC is a module that simplifies working with plain JDBC by removing repetitive boilerplate code — like opening/closing connections, handling exceptions, and closing statements — using a helper class called JdbcTemplate.

BLOCK DIAGRAM — SPRING JDBC FLOW
Java Application
→
JdbcTemplate
(Spring JDBC)
→
DataSource
(Connection Pool)
→
Database
(MySQL / Oracle etc.)
JdbcTemplate internally manages the connection, executes the SQL query, maps results, and closes resources automatically.
Point 6.2

Example: Spring JDBC using JdbcTemplate

Java Student.java (Model) 
public class Student {
    private int id;
    private String name;
    // getters and setters
}
Java StudentDao.java 
import org.springframework.jdbc.core.JdbcTemplate;

public class StudentDao {
    private JdbcTemplate jdbcTemplate;

    public void setJdbcTemplate(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    public void addStudent(int id, String name) {
        String sql = "INSERT INTO student (id, name) VALUES (?, ?)";
        jdbcTemplate.update(sql, id, name);
        System.out.println("Student added successfully!");
    }
}

Point 6.3

Spring + Hibernate Integration

📖 DEFINITION

Hibernate is an ORM (Object Relational Mapping) tool that maps Java objects directly to database tables, so we don't need to write raw SQL for basic operations. Spring integrates with Hibernate to manage the SessionFactory and transactions automatically.

BLOCK DIAGRAM — SPRING + HIBERNATE FLOW
Java Object
(POJO / Entity)
→
Hibernate
(ORM Layer)
→
SessionFactory
(managed by Spring)
→
Database Table
Spring manages the SessionFactory and transactions, while Hibernate converts Java objects into SQL and back — this combination is called the ORM pattern.
Point 6.4

Example: Spring + Hibernate Implementation

Java Student.java (Entity) 
import javax.persistence.Entity;
import javax.persistence.Id;

@Entity
public class Student {
    @Id
    private int id;
    private String name;
    // getters and setters
}
Java StudentDao.java (using HibernateTemplate / Session) 
import org.hibernate.Session;
import org.hibernate.SessionFactory;

public class StudentDao {
    private SessionFactory sessionFactory;

    public void setSessionFactory(SessionFactory sf) {
        this.sessionFactory = sf;
    }

    public void saveStudent(Student student) {
        Session session = sessionFactory.openSession();
        session.beginTransaction();
        session.save(student);
        session.getTransaction().commit();
        session.close();
        System.out.println("Student saved using Hibernate!");
    }
}
XML applicationContext.xml (Hibernate SessionFactory bean) 
<bean id="sessionFactory"
      class="org.springframework.orm.hibernate5.LocalSessionFactoryBean">
    <property name="dataSource" ref="dataSource"/>
    <property name="packagesToScan" value="com.example.model"/>
    <property name="hibernateProperties">
        <props>
            <prop key="hibernate.dialect">
                org.hibernate.dialect.MySQL8Dialect
            </prop>
            <prop key="hibernate.hbm2ddl.auto">update</prop>
        </props>
    </property>
</bean>

<bean id="studentDao" class="StudentDao">
    <property name="sessionFactory" ref="sessionFactory"/>
</bean>
Point 6.5

Spring JDBC vs Spring + Hibernate

Basis Spring JDBC Spring + Hibernate
SQL writing Developer writes SQL manually Hibernate generates SQL automatically
Mapping Manual mapping of ResultSet to objects Automatic Object-to-Table mapping (ORM)
Speed to develop Good for simple, small queries Faster for complex applications with many tables
Database independence SQL may need changes if database changes Mostly database-independent (just change dialect)
🎓 EXAM TIP

If a question asks to "differentiate JDBC and Hibernate," always mention: JDBC = manual SQL + manual mapping; Hibernate = automatic SQL generation + ORM mapping.
